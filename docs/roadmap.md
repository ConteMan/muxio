# Roadmap

> 本文维护范围和里程碑完成标准；具体任务与进度使用 GitHub Issues / Milestones。

## v0.1 范围

### In

- Go 单二进制、SQLite、CLI 和本地 HTTP API。
- 采集源配置、手动运行、固定间隔调度和有界重试。
- file 与 RSS/Atom 两个内置连接器。
- 幂等采集、不可变版本、来源追溯和崩溃恢复。
- 运行记录与结构化日志，可按运行追溯到失败原因。
- 配置文件读写与校验。
- 标题与正文全文搜索。
- JSONL 导出。
- CLI 状态表、运行历史、健康检查。
- 独立 Web 设置中心：观察运行与日志，管理配置。

### Out

- Clipboard、ICS、通用 HTTP JSON 和浏览器自动化。
- 外部连接器 SDK、动态插件 ABI。
- MCP Server、Agent 主动执行。
- 摘要、标签、承诺识别等内容理解。
- 附件、大型二进制、多用户、云同步和远程管理。
- 浏览器扩展、桌面端和移动端。

## 里程碑

| 里程碑 | 内容 | 完成标准 |
|---|---|---|
| M0 基础 | 仓库、文档合同、CLI、健康 API、统一门禁 | `muxio version`、`muxio serve` 可用，`selftest` 与 CI 全绿 |
| M1 存储与可观测地基 | migration、sources/captures/runs、结构化日志、配置系统 | 每次运行可追溯到状态、计数与失败原因，配置可读可写可校验 |
| M2 本地 API | `/api/v1` 覆盖 sources、runs、logs、config 的读写 | 主要能力均可由 API 完成，CLI 不依赖表结构 |
| M3 Web 设置中心 | 前端工具链、运行与日志观察、配置编辑 | 不访问 SQLite，仅消费已发布 OpenAPI；日常管理可在浏览器完成 |
| M4 真实采集 | 连接器合同、file、RSS/Atom、调度、重试、checkpoint | 两个连接器重复运行幂等，失败不推进 checkpoint，重启无悬挂运行 |
| M5 搜索与导出 | FTS5 投影、搜索命令、JSONL 导出 | 内容可搜索，数据可完整带走 |
| M6 稳定发布 | 故障测试、迁移备份、跨平台构建、GoReleaser | 干净机器可完成采集、搜索、导出和升级验证 |

## 顺序说明

2026-08-10 由维护者重排：可观测性与配置管理从原 M3 / M5 提前，真实采集、搜索与导出相应后移。

重排的原因是验收方式，不是范围变化：维护者需要以普通用户视角在界面上确认系统行为，而不是依赖终端输出。上表的 In / Out 边界没有改变。

重排带来一个必须提前说明的预期：M3 完成时尚无自动采集，面板中的运行记录来自 `muxio import`。要看到按计划自动执行的采集，需要 M4。

## M1 切片顺序

M1 分片交付，每片一个 Spec、一个可独立评审和回滚的 PR；前一片验收通过后才开下一片。

| 顺序 | 切片 | 承载 | 验证的核心假设 |
|---|---|---|---|
| 1 | 存储地基与幂等导入 | [Spec 002](specs/002-storage-foundation.md) | 重复写入不产生重复记录，内容变化保留新版本 |
| 2 | 运行记录与结构化日志 | [Spec 003](specs/003-runs-and-logging.md) | 每次运行可追溯，重启不留悬挂运行，失败原因可查 |
| 3 | 配置系统 | [Spec 004](specs/004-configuration.md) | 配置可读可写可校验，界面写入与手工编辑不互相覆盖 |

凭据存储的约束已由 [ADR-005](decisions/005-config-and-credential-storage.md) 立好，但首期两个连接器都不需要认证，因此实现推迟到 M4 出现需要认证的来源时。

| 顺序 | 切片 | 承载 | 验证的核心假设 |
