## 工具限制

Pencil 的 `execute` 的 `filePath` 参数只对**已存在**的 `.pen` 文件生效。指向不存在的路径时不报错，而是静默作用于当前活跃的画布编辑器。

因此 `docs/design/ui/prototypes/muxio-ui-explorations.pen` 必须先由维护者在 Pencil 应用中创建，之后 Agent 才能通过 `filePath` 定向操作它。在此之前的任何 `execute` 都会落到别的项目文件上。

本轮曾因此把四个 frame 误建到 `conflow-ui.pen`，已全部删除；conflow 的顶层节点数回到 32，`git diff` 为空，磁盘文件未被改动。

## 已验证的观察（低保真，待在正式源文件中重做）

以下基于 fixtures 的真实数据渲染后得出，不是纸面推断。

### 状态徽标

圆点 + 文字的组合在浅色与深色下均可读。七种状态用七种色相，但**颜色只是辅助**，文字承载语义——去掉颜色后信息不丢失。这满足"不单靠颜色"的验收。

深色下的色值必须单独提亮（如 `succeeded` 从 `#1a7f52` 提到 `#4fbf8a`），直接复用浅色值在深色底上对比度不足。这印证了"深色不是浅色反相"的约束。

### 方向 A（单一外壳）与方向 B（观察与设置分离）

用同一份 7 行 fixture、同样的列宽渲染 1440px 后：

| | 方向 A | 方向 B |
|---|---|---|
| 表格可用宽度 | 1156px | 1376px |
| 数据实际占用 | 约 800px | 约 800px |
| 右侧空白 | 约 350px | 约 570px |
| 导航 | 左栏常驻 | 右上角一个文字入口 |

**关键发现：B 方向多出的 220px 没有被数据用上。** 七列数据在两种布局下都只占约 800px，B 的"全宽"优势不存在，代价却是导航退化成右上角一个弱入口。

对一个只有"运行"和"设置"两个区的应用，A 的左栏占用是有回报的——它让第二个区始终可见，而 B 把设置藏进了一个需要主动寻找的角落。

初步倾向 A，但**必须在正式源文件中补齐 Run Detail、Settings、Narrow、Appearance、Dark 后再下结论**：Settings 的多栏结构在 A 的左栏之下会形成"栏中栏"，这是 A 尚未被检验的风险点。
