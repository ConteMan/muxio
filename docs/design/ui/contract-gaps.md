# M3 UI 合同状态与缺口

状态基于对 `api/openapi.yaml`、`internal/api/` 与 `internal/store/sqlite/` 的静态核对。"已实现"仅表示所列最小合同有对应实现与测试，不延伸为未验证的浏览器体验声明。

面板只能经 `/api/v1` 取数（ADR-001）。任何画板都不得设计出后端尚不存在的能力——发现缺口时记在此处，由 Spec 决定补齐还是延期，而不是在设计里假装它存在。

| 编号 | 最小合同 | 当前事实 | 状态 | 下一步 |
|---|---|---|---|---|
| CG-01 分页方向 | 同一个 `before` 参数在所有列表端点上语义一致 | `runs` 与 `sources` 按 `id DESC` 且 `id < before`；`runs/{id}/events` 按 `id ASC` 且 `id > before`。两者方向相反，而 OpenAPI 对 `before` 的描述是"id 低于此值"，对 events 是错的 | **缺陷** | 事件的游标改名为 `after` / `next_after` 并在 OpenAPI 中分别描述；这是已发布端点的字段语义变更，命中决策卡点第 5 条 |
| CG-02 事件截断可见 | 运行事件达到上限时，界面能区分"这次很安静"与"事件被截断了" | 后端在第 1000 条时写入一条 `event log truncated` 的 warn 事件，API 原样返回 | 已实现 | 画板必须把这条事件设计成显式的截断提示，而不是混在普通事件流里 |
| CG-03 运行事件级别过滤 | 只看 error 级事件 | 无过滤参数，只能取回全部再由前端筛 | 延期 | 单次运行上限 1000 条，前端过滤可接受；出现真实性能证据前不加参数 |
| CG-04 来源详情 | 读取单个来源及其最近运行 | 只有 `GET /api/v1/sources` 列表，无 `/{id}` | 延期 | 首期面板不设来源详情页；M4 引入连接器配置后再定 |
| CG-05 采集内容 | 查看某条 capture 的正文 | 无端点，Spec 005 明确排除 | 延期 | 面板不得出现指向内容的入口或占位；分页、脱敏与体积问题由独立 Spec 承载 |
| CG-06 触发采集 | 从界面发起一次采集 | 无端点，尚无连接器与调度 | 延期 | M4 之前面板是纯观察；不得以 disabled 按钮暗示即将可用 |
| CG-07 配置生效时机 | 界面明确告知写入何时生效 | 配置在进程启动时读取一次，无热重载（Spec 004 非目标） | 已实现（合同收窄） | 画板必须在写入成功后明确提示需重启 `muxio serve`，不得暗示立即生效 |
| CG-08 环境覆盖 | 界面能解释"改了文件为什么没生效" | `GET /api/v1/config` 每项返回 `origin`；`PUT` 后重新加载，被环境覆盖的项 `origin` 仍为 `env` | 已实现 | 画板必须把 `env` 覆盖设计成显著状态而非附注 |
| CG-09 写入冲突恢复 | 冲突时不覆盖，并提供可执行的恢复动作 | `PUT` 要求 `If-Match`，冲突返回 `412` 并在响应头给出当前 `ETag` | 已实现 | 画板需把 `412` 设计成"重新读取并重放编辑"的明确路径，而不是一句错误文案 |
| CG-10 全局概览 | 首屏给出总量级（来源数、记录数、最近一次采集） | 无聚合端点；`sources` 与 `runs` 只能分页取回 | 延期 | 首期面板首屏即运行列表，不做仪表盘；真出现需求时另开 Spec 定义聚合语义 |

## 当前跨层状态

- CG-01 是本轮唯一的实现缺陷，且属于已发布契约的语义修正。设计探索可以先按"事件向后翻页"的正确语义画，但实现必须先修契约。
- CG-02、CG-07、CG-08、CG-09 是四个**必须被设计显式承载**的状态。它们在后端已经是事实，如果画板不表达，用户就会遇到"界面说成功了但什么都没变"这类无法自解释的情况。
- CG-03 至 CG-06、CG-10 全部延期。画板不得为它们留占位、disabled 控件或导航入口。

## 后续顺序

1. 修 CG-01：改 OpenAPI 与实现，事件游标独立命名。
2. 在此基础上冻结设计基线，CG-02、CG-07、CG-08、CG-09 必须在画板中可定位。
3. 实现回归对齐冻结基线。
