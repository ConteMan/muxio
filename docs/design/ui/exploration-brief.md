# Muxio 面板结构探索 Brief

> 状态：结构探索待启动（2026-08-11）
> 范围：`muxio serve` 提供的本地面板的结构与交互。不改变 API 契约、CLI 行为或采集语义。
> 技术边界：React + TypeScript + Base UI + Tailwind；产物由 Go `embed` 进单二进制（ADR-007），运行时不依赖 Node，**不请求外部 CDN、字体或脚本**——字体只能用系统字体栈或内联资源。

## 1. 当前事实与证据等级

### 产品事实

- 面板只服务维护者本人，在本机 loopback 上，无认证、无多用户。
- 数据全部来自 `/api/v1`：来源、运行、运行事件、生效配置。面板不读 SQLite（ADR-001）。
- 本期**没有**采集触发、采集内容查看、来源编辑与聚合概览（CG-04、CG-05、CG-06、CG-10）。面板是纯观察加配置。
- 运行由 `muxio import` 产生。要看到按计划自动执行的采集需要 M4——画板不得暗示它已存在。
- 配置写入进文件但**不热重载**，生效需重启进程（CG-07）。
- 被环境变量覆盖的设置项，写文件不改变生效值（CG-08）。

### 设计资产的使用规则

- `web/src/` 的当前实现是从 Spec 007 直接写成的，**没有经过设计阶段**。它是能力事实源，不是目标结构，也不是视觉基线。
- 本轮结束前，`docs/design/ui/prototypes/muxio-ui.pen` 尚不存在。产出后它是唯一可编辑视觉事实源。
- PNG 只作为评审快照，不得作为视觉、组件或完成度的事实源。

## 2. 探索目标

让维护者在打开面板后的几秒内判断"最近一次采集是否可信"，并在需要时一路追到具体某一行为什么被拒绝；同时不牺牲他理解当前配置为何如此的能力。

本轮需要回答：

1. 打开面板的第一屏应该是运行列表，还是先给一个"最近一次采集怎么样"的结论？
2. 一个 `succeeded` 但 `failed_count > 0` 的运行，怎样才不会被读成"完全没问题"？
3. `interrupted` 与 `partial` 怎样表达"数据没丢，只是没跑完"，而不是让人以为要重来？
4. 运行详情与事件时间线应该是独立页面，还是列表内展开？哪种在 1001 条事件与 96 字符消息下仍然可读？
5. 设置页的 `origin` 是次要元数据还是主要信息？`env` 覆盖如何强到不会被忽略，又不至于像报错？
6. 七列的运行表在 390px 下如何取舍，而不是让页面横向滚动？
7. 设置采用多栏导航后，只有 4 个配置项时如何不显得空洞，同时为 M4 的来源管理留出扩展位？
8. 主题与语言的入口放在哪里：设置里的一项，还是全局常驻控件？
9. 中英文文本长度差异（"运行历史" 4 字 vs "Run history" 11 字符）如何不在任一语言下打破布局？

非目标：动效、品牌视觉、移动端专属交互、仪表盘图表、实时推送、除中英文外的语言。

## 3. 用户与核心任务

单一用户：项目维护者，熟悉终端，装了 Muxio 在自己机器上跑。他已经有 `muxio runs` 与 `muxio config show` 可用——**面板必须比终端更快回答问题，否则没有存在理由**。

核心任务见 [flows/m3-panel.md](flows/m3-panel.md) 的 Q1–Q6。

## 4. 两个结构方向

维护者已指定设置页采用 Cherry Studio 那类多栏导航（2026-08-11）。因此 A/B 不再比较"要不要多栏"，而是比较**多栏之下运行观察与设置如何共处**。

需要先记下一个观察：Cherry Studio 本身不是固定三栏。它的 MCP 页是三栏（分类 → 二级列表 → 内容），外观页是两栏（分类 → 内容）——**中间栏按需出现**，只在某个分类的条目多到需要先选一个时才存在。Muxio 当前只有 4 个配置项，固定三栏会有一整栏是空的；而 M4 的来源管理正好需要那一栏。

**方向 A：单一外壳。** 左栏是全局导航，运行与设置是并列的两个区。设置区内部再分组，条目多时中间栏出现。运行观察与设置共用同一套导航语法。

**方向 B：观察与设置分离。** 运行观察是全宽的主界面（列表 + 详情），设置是独立的多栏区域，从顶部入口进入——接近 Cherry Studio 把"设置"作为一个独立模式的做法。

两个方向用**相同的 fixture、相同的状态、相同的视口、相同的语言**对比，只回答结构问题，不做视觉定稿。

## 5. 视觉参考

风格取向：简洁、信息密度高、克制的色彩。参考对象与具体借鉴点：

| 参考 | 借鉴什么 | 不借鉴什么 |
|---|---|---|
| Cherry Studio | 左栏分类 + 中间栏按需的设置结构；分组标题的层级表达 | 条目数量与功能面——Muxio 没有那么多配置 |
| Linear | 设置页的两栏节奏、行式设置项的对齐与留白 | 品牌色与动效 |
| Raycast 偏好设置 | 本地工具的设置密度，键盘可达 | 桌面原生控件 |
| Vercel Dashboard | 状态徽标与表格的信息密度 | 多租户导航层级 |

一律使用系统字体栈：CSP 与"零外部请求"约束禁止加载任何 Web 字体。

## 6. 阶段门禁
