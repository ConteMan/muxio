# M3 面板主路径与状态矩阵

面板的用户只有一个：维护者本人，在自己的机器上。他不是在监控生产系统，而是在回答几个具体问题。设计以这些问题为准，不以"仪表盘应该有什么"为准。

## 用户要回答的问题

| 编号 | 问题 | 现在只能怎么回答 | 面板应该怎么回答 |
|---|---|---|---|
| Q1 | 最近一次采集成功了吗 | `muxio runs` | 打开面板第一屏 |
| Q2 | 这次为什么失败 | `muxio runs show N` | 从列表点进去 |
| Q3 | 哪一行数据有问题、错在哪 | `muxio runs show N` 逐条读 | 运行详情的事件时间线 |
| Q4 | 上次那个进程被杀了，数据还在吗 | 读 `interrupted` 状态与计数 | 状态徽标 + 已提交计数 |
| Q5 | 当前按什么设置在跑 | `muxio config show` | 设置页 |
| Q6 | 我改了配置为什么没生效 | 看 `config show` 的来源列 | 设置页的来源标注与覆盖警告 |

Q6 是最容易被界面做砸的一个：如果只显示值不显示来源，用户会改文件、重启、发现没变，然后无从下手。

## 主路径

```
打开面板
  → 运行列表（Q1）
    → 看到 failed_count > 0 或非 succeeded 状态
      → 运行详情（Q2）
        → 事件时间线（Q3）
          → 定位到具体行号与原因
  → 设置（Q5）
    → 发现某项来源是 env（Q6）
      → 知道要先 unset 环境变量
```

面板到此为止。**触发采集、查看采集内容、编辑来源都不在本期**（CG-04、CG-05、CG-06）。

## 状态矩阵

### 运行列表

| 状态 | 触发条件 | 界面必须表达 |
|---|---|---|
| 加载中 | 首次进入或翻页 | 与"空"可区分 |
| 空 | 从未导入过 | 说明下一步做什么，而不是只说"暂无数据" |
| 正常 | 有运行 | 见下方状态徽标 |
| 单页到底 | `next_before` 为 null | 下一页不可点 |
| 多页 | `next_before` 非 null | 可前后翻，且"上一页"不靠重算 |
| 请求失败 | 网络或 5xx | 错误原因 + 可重试 |
| 存储不可达 | `/readyz` 非 200 | 与普通请求失败区分：这时所有数据都不可信 |

### 运行状态徽标

七种状态各自的含义必须能被读出来，且不能只靠颜色：

| 状态 | 含义 | 视觉要求 |
|---|---|---|
| `succeeded` | 全部处理完，可能仍有失败行 | 成功，但 `failed_count > 0` 时失败数必须显眼 |
| `partial` | 已提交部分记录后中止 | 与 succeeded 明确区分 |
| `failed` | 未提交任何记录即中止 | 与 partial 明确区分 |
| `interrupted` | 进程被杀，心跳停滞后回收 | 强调"已提交的数据仍在" |
| `canceled` | 用户主动取消 | 中性，不是错误 |
| `running` | 进行中 | `finished_at` 为 null，不显示时长或显示"进行中" |
| `queued` | 已排队未开始 | 首期不会出现，但状态机允许 |

### 运行详情

| 状态 | 界面必须表达 |
|---|---|
| 进行中 | 完成时间与时长为"进行中"，不是空或 1970 |
| 有 `last_error` | 错误独立呈现，不混在计数里 |
| 无事件 | 明确的空态，与加载中、出错区分 |
| 事件被截断 | 显式提示还有多少失败行没有对应事件（CG-02） |
| 长事件消息 | 不撑破布局，允许换行或自身滚动 |
| 运行不存在 | 404 时给出返回列表的路径，不是白屏 |

### 设置

| 状态 | 界面必须表达 |
|---|---|
| 文件不存在 | 显示"使用默认值，文件尚未创建"，不是错误 |
| 来源为 `default` | 中性 |
| 来源为 `file` | 中性 |
| 来源为 `env` | **显著警告**：改文件不会生效，需先 unset（CG-08） |
| 来源为 `flag` | 说明由命令行传入，重启后取决于启动参数 |
| 长路径 | 配置文件路径可完整读取，窄屏不横向溢出 |

配置写入（下一片）追加：dirty、保存中、成功需重启（CG-07）、`412` 冲突恢复（CG-09）、字段级校验错误。

## 视口

| 视口 | 宽度 | 验收要点 |
|---|---|---|
| Desktop | 1440px | 六位数计数对齐不换行；长来源名与长事件消息不裁切主信息 |
| Narrow | 390px | 运行表格不造成页面级横向溢出；配置路径与长事件消息可读；导航可达 |

窄屏不是"把桌面稿缩小"。运行列表在 390px 下有七列，必须先决定哪些列保留、哪些折叠，而不是让页面横向滚动。
