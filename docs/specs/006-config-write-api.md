# Spec 006：配置写入 API

- 状态：已实现
- 关联：Roadmap M2 第 2 片、ADR-005、ADR-006

## 问题

配置目前只能经 CLI 修改。M3 设置中心要在浏览器里改设置，需要一个写入端点。

写入端点必须先解决一个问题：界面读到配置、用户编辑、提交，这段时间里配置可能已被手工编辑或另一个界面改过。默认覆盖会静默丢掉别人的修改。

## 行为

### 版本标识

`GET /api/v1/config` 返回 `ETag`，值是配置文件内容的指纹（ADR-006）。文件不存在时返回代表"尚无文件"的固定值。

### 写入

```
PUT /api/v1/config
If-Match: "<etag>"
Content-Type: application/json

{ "settings": [ { "key": "log.level", "value": "debug" }, ... ] }
```

- 请求必须带 `If-Match`。缺失返回 `428`：无条件写入正是要防止的行为。
- `If-Match: *` 返回 `400`。它的标准含义是"资源存在即可"，等于放弃冲突检测，而本端点存在的理由就是不放弃。
- `If-Match` 与当前文件指纹不符返回 `412`，并在响应体中给出当前值，便于界面提示"已被他人修改"。
- 请求必须给出全部已知设置。缺失字段返回 `400` 并指出缺哪个：漏传一个字段而被静默重置为默认值，比一次失败危险得多。
- 未知的 key 返回 `400`。
- 值不合法返回 `400`，`field` 为对应的设置键。
- 成功返回 `200`、新的配置视图与新的 `ETag`。

写入沿用 CLI 的路径：整份重新渲染，临时文件加原子 rename，权限 `0600`。

### 环境覆盖

写入的是文件。若某项当前被环境变量覆盖，写入成功但生效值不变。响应中的 `origin` 会如实显示 `env`，界面据此提示用户，而不是让用户以为改动没生效。

### 请求体限制

请求体上限 1 MiB。配置只有几十行，更大的请求体只可能是错误或恶意。

## 边界与非目标

- 不实现凭据写入。`credentials.toml` 在出现需要认证的来源前不创建（ADR-005）。
- 不实现来源的增删改；来源定义进配置由 M4 承载。
- 不实现认证。服务仍只监听 loopback。
- 不实现配置热重载：写入后新值在下次进程启动时生效，响应中如实反映这一点。
- 不实现前端。

## 验收

- `GET /api/v1/config` 返回 `ETag`；内容未变时重复请求得到相同的值。
- 带正确 `If-Match` 的 `PUT` 写入成功，文件内容改变，注释仍在，权限仍为 `0600`。
- 不带 `If-Match` 返回 `428`，文件未被修改。
- `If-Match` 过期（写入前文件被外部改动）返回 `412`，文件保留外部改动，响应给出当前 `ETag`。
- 缺少任一设置返回 `400` 并指出缺失的 key，文件未被修改。
- 未知 key 与非法值返回 `400` 且 `field` 正确，文件未被修改。
- 配置文件此前不存在时，用哨兵 `ETag` 可以成功创建；用该哨兵重复写入第二次返回 `412`。
- `If-Match: *` 返回 `400`，文件未被修改。
- 被环境变量覆盖的设置写入成功，响应中该项 `origin` 仍为 `env`。
- 请求体超过 1 MiB 返回 `413`。
- OpenAPI 描述该端点及其全部响应码，校验通过。
- `./scripts/selftest.sh` 全绿，含条件写入、冲突、校验与哨兵创建的自动化测试。
