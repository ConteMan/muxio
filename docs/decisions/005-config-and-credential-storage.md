# ADR-005：配置与凭据的存储方式

- 状态：已接受
- 日期：2026-08-10

## 背景

Web 设置中心需要读写配置，这带来两个此前被推迟的问题：配置的事实源是文件还是数据库；界面与手工编辑同时修改配置时谁赢。

凭据在首期没有实际需求——file 与 RSS/Atom 两个内置连接器面向本地文件和公开 Feed，都不需要认证。但存储位置的约束必须提前立好：第一个需要认证的来源出现时，如果没有既定护栏，凭据会被顺手写进来源配置并随之进入数据库、备份、导出和日志，而那时再撤回需要用户重新录入全部密钥。

因此本 ADR 同时决定配置事实源与凭据存储方式，前者立即实施，后者是约束而非待建功能。

## 决策

### 配置

`config.toml` 是配置的唯一事实源，数据库不保存配置。界面写入等同于重写该文件：先写临时文件再原子 rename。

写入前校验文件修改时间与读取时是否一致，不一致则拒绝写入并报告冲突，由人决定如何合并。

### 凭据

凭据存放在独立的 `credentials.toml`，权限 `0600`，与 `config.toml` 分离，且不进入 SQLite。该文件在第一个需要认证的来源出现前不会被创建。

凭据字段支持间接引用：`${env:NAME}` 读取环境变量，`${cmd:...}` 执行命令取值。这让使用外部密码管理器的用户不必把密钥交给 Muxio 保管。

不使用操作系统钥匙串。

## 后果

### 关于不用钥匙串

- macOS Keychain 需要通过 Security.framework 走 cgo，与 ADR-004 承诺的 `CGO_ENABLED=0` 跨平台发布直接冲突。
- Linux 侧依赖 D-Bus 与 Secret Service，headless 与服务器环境不可用，与"能在个人设备长期稳定运行"冲突。
- 三个平台的行为、错误语义和迁移方式都不一致，会让备份与恢复无法给出统一承诺。

### 关于明文

- 磁盘上的凭据是明文，保护依赖文件权限与用户自己的磁盘加密。这与 AWS CLI、gh、npm 和 Docker 的既有做法同级，但必须在 README 与设置界面显式告知，不得暗示存在加密保护。
- 不落盘加密的替代路径是 `${env:...}` 与 `${cmd:...}`，需要更强保护的用户走这条。

### 全局约束

- 凭据不入数据库，因此不进入备份、导出、搜索和采集记录。
- API 永不返回完整凭据，只返回是否已设置与掩码后的尾部片段。
- 日志、错误信息和运行事件必须对凭据脱敏；`${cmd:...}` 的输出同样视为凭据。
- 分离两个文件的目的，是让 `config.toml` 可以安全地进入版本控制与问题反馈，而 `credentials.toml` 永远不行。
