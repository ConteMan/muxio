# ADR-007：Web 面板以嵌入式产物随二进制交付

- 状态：已接受
- 日期：2026-08-11
- 关系：取代 [ADR-001](001-lightweight-monorepo.md) 中关于 Web 独立发布的部分，其余部分继续有效

## 背景

ADR-001 决定核心与 Web 同仓但"独立构建、运行、测试、版本和发布"。当时 Web 尚未开工，发布形态是按一般 Monorepo 惯例推定的。

真正要交付面板时，这条与 ADR-002 的承诺发生冲突：ADR-002 说 Muxio 跨平台发布**单文件程序**。若 Web 独立发布，用户装完 `muxio` 还要另外托管一份静态资源才能看到面板，本地优先的个人工具不该有这个步骤。

维护者在两个同类项目上的实践也一致指向另一条路：conflow 与 repolens 都是本地优先的 Go 工具，都把前端构建产物 `go:embed` 进单二进制；ceave 的管理后台独立部署，但它是云产品，前提不同。

## 决策

Web 面板的构建产物随二进制交付。

- `web/` 保存前端源码，仍是独立工程：独立的依赖、构建、类型检查和测试。
- 构建产物落在 `internal/webui/assets/` 并提交进仓库，由 `//go:embed` 打进二进制。
- `muxio serve` 同时提供 `/api/v1` 与面板，无需任何额外进程。

ADR-001 的其余部分不变：核心与 Web 仍在同一仓库、仍是边界严格的两个工程、`api/openapi.yaml` 仍是唯一跨工程合同、Web 仍不得读取 SQLite。

## 后果

- 用户装一个二进制，`muxio serve` 后浏览器打开即用。
- **Go 构建仍然不依赖 Node**：产物已在仓库里，`go build` 只是嵌入既有文件。这条硬规则得以保留，而不是被绕过。
- 代价是仓库中存在构建产物，前端改动的 diff 会包含压缩后的 JS 与 CSS，评审时噪声较大。
- 产物过期是新的失败模式：源码改了而产物没重建，二进制里就是旧界面。因此门禁必须重新构建并比对产物，不一致即红灯。
- 前端与核心不再有独立版本号。面板的行为差异通过 `/api/v1` 的契约版本表达，而不是前端自己的版本。
- 若未来出现独立部署面板的真实需求（例如远程访问），需要新增 ADR，并同时处理 ADR-002 的监听地址约束与认证。
