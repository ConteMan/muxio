# ADR-006：用内容指纹检测配置的并发修改

- 状态：已接受
- 日期：2026-08-11
- 关系：细化 [ADR-005](005-config-and-credential-storage.md) 的实现手段，不推翻其决策

## 背景

ADR-005 决定配置写入前校验文件的修改时间，以免界面覆盖手工编辑。实现 HTTP 写入端点时，修改时间暴露出三个问题：

- **精度不一致**：不同文件系统的时间戳精度从纳秒到秒不等，同一份代码在不同机器上的检测灵敏度不同。
- **误报**：备份、同步和归档工具会在内容未变的情况下改写修改时间，用户会看到一次并不存在的冲突。
- **漏报**：在秒级精度的文件系统上，一秒内的两次写入可能带有相同的时间戳，真实冲突反而检测不到。

同时，HTTP 的条件请求本就使用实体标签而非时间戳来表达"我基于这个版本修改"。

## 决策

并发检测改用配置文件内容的 SHA-256 指纹。文件不存在时指纹是一个固定的哨兵值，用于表达"我认为此文件尚不存在"。

CLI 与 HTTP 使用同一实现。HTTP 层把指纹暴露为 `ETag`，写入要求 `If-Match`。

## 后果

- 只改时间戳不改内容不再触发冲突，同一秒内的真实改动不再被漏掉。
- 检测行为不再随文件系统变化，跨平台表现一致。
- `ETag` 是强验证器：值相同意味着字节完全相同。
- 代价是每次写入前多读一次文件并计算哈希。配置只有几十行，开销可以忽略。
- ADR-005 的其余决策不变：配置仍以文件为唯一事实源，写入仍是临时文件加原子 rename，冲突仍然拒绝写入并交由人裁决。
